# 星球水体配色与岸带重构规划（河道 / 海岸 / 入海口）

> 参考图：`temp/river10.png`（RimWorld 原图截图，2244×1469，含陆地、河流、入海口、海洋）
> 前序文档：`docs/planet_rivers_plan.md`（§20–§24 河宽分级 / 形状 / 岸线裁剪）、
> `docs/planet_textures_plan.md`（§3⑥ 近岸白噪带）
> 状态：**已实施（2026-10-24，见 §11 实施记录）**
> 关联文件：`planet.gd`、`planet_rivers.gdshader`、`planet_surface.gdshader`、
> `tools/test_planet_rivers.gd`、`tools/test_planet_texture.gd`
> 拍板结论：**① 做河岸（窄河可牺牲水芯）② `RIVER_HALF_MAX` 不动 ③ 深海严格对齐 #303949**

## 0. 结论摘要（先看这段）

参考图不是"给河口做过渡"，而是**让河流和海在颜色上根本无法区分**：

| 层 | 参考图做法 |
|---|---|
| 河水 | 纯色 **#495264**，从头到尾一个值，无纹理无动画 |
| 河岸 | 两侧各一条纯色带 **#565860**，宽度 ≈ 总河宽的 13%/侧 |
| 近岸海水 | **#495264**（与河水逐像素相同） |
| 深海 | 随离岸距离**缓慢变暗**到 #303949，跨度约 8–14 个贴片 |
| 水面噪声 | 存在但极弱：σ ≈ 1–3/255 |
| 入海口 | **没有任何特殊处理**，就是两段同色几何拼在一起 |

由此得出三条我们该改的东西：

1. **河水改 #495264**（现在 #327bc7，亮了、艳了一个数量级）。
2. **岸边带从"白雾"改成"浅水色渐变"**：参考图最大抬升 +25/255 且**保持蓝色的饱和度**；
   我们现在抬到 #7a8495（+69/255）且**往灰白走**——这就是"用力过猛"的确切含义。
3. **加河岸带**（现在完全没有），并**删掉河口过渡逻辑**：同色之后天然无缝，
   不需要任何 blend。

上一轮我提的「河口按弧长混到海色（COLOR.b / mouth_fade）」和「河口局部抑制白雾带」
**在本方案里全部作废**——那是"两种材质之间打补丁"的思路，参考图根本不存在这个问题。

## 1. 参考图实测

### 1.1 河流横剖面（原图 x=400，竖直切过河）

| y 区间 | 像素数 | 实测色 | 判定 |
|---|---|---|---|
| 390–406 | 17 | #8b7050 附近（σ≈5） | 陆地（带细颗粒噪声） |
| 407–414 | 8 | **#56585f** 恒定 | **河岸** |
| 415–457 | 43 | **#495264** 恒定 | 河水 |
| 458–465 | 7 | **#565860** | 河岸 |
| 466– | — | #8b7050 附近 | 陆地 |

- 河岸与河水之间、河岸与陆地之间各有 **1px 抗锯齿过渡**，没有渐变、没有噪声。
- 河水内部 **完全恒定**：整张图里河水像素的 min/max 只有 #49525d–#525764（差值全部来自边沿 AA）。

### 1.2 河岸宽度是否随河宽缩放

| x | 河总宽（含两岸） | 单侧岸宽 | 岸宽/总宽 |
|---|---|---|---|
| 150 | 49 px | 7 px | 14.3% |
| 400 | 59 px | 8 / 7 px | 13.6% |
| 450 | 60 px | 8 / 7 px | 13.3% |
| 700 | 51 px | 6 / 6 px | 11.8% |

→ **按比例缩放**（≈13%/侧），不是固定像素宽。所以它可以直接做成 ribbon 上的一段 UV 区间。

**河岸色可以推导出来**（不是魔法数字）：

```
mix(河水 #495264, 典型旱地 #8b7050, 0.20) = #565860
实测河岸                                  = #56585f
```

即「河岸 = 河水向陆地色混 20%」——一条规则，换配色时自动跟着走。

### 1.3 海岸剖面（用离岸距离场，按距离分箱统计；原图 2244 宽）

| 离岸距离 | 平均色 | σ |
|---|---|---|
| 4 px | #515662（与陆地混色的 AA 带） | 4.3 |
| 8 px | #4a5364 | 2.4 |
| 12 px | **#495265** | 1.1 |
| 48 px | #475264 | 1.6 |
| 112 px | #454f62 | 2.3 |
| 200 px | #414b5e | 2.5 |
| 300 px | #3d475a | 2.6 |
| 400 px | #394355 | 2.7 |
| 520 px | #363f51 | 3.4 |
| 最深处 | **#303949** | 1.0 |

三个结论：

1. **海岸没有"带"，只有一整片缓慢的浅→深渐变**。岸线处就是最浅的值，往外单调变暗，
   大约 500 px 走完 75%，到 ~800 px 才稳定在 #303949。
2. 渐变**几乎线性**，不陡、不亮、不白。
3. 水面噪声 σ ≈ 1–3/255（约 0.4%–1.3% 亮度），且**离岸越远越明显**——它更像水体本身的
   细微斑驳，而不是"岸边白雾"。

**深海与浅水的比例关系**：

```
deep / shallow = (48,57,73) / (73,82,100) = (0.658, 0.695, 0.730)
```

→ 深海不是"另一种颜色"，而是**浅水色乘一个接近均匀的暗化系数**（蓝通道衰减最慢，
所以深海反而更蓝一点）。

### 1.4 入海口：确认没有任何过渡

原图 y=420 横剖穿越入海口：

```
x 690..724  #495264  ← 河水（恒定）
x 726       #475365
x 728       #495266
x 730       #4a5368
x 732..     #465164 / #475164 / #485366 ... ← 海水（σ≈2 的噪声）
```

河水与海水在同一像素位置上的差值 **≤3/255**，即噪声量级以内。**跨过去看不出来**。

河岸带一直延伸到岸线然后自然结束（岸线处被六边形海岸切断），参考图也没有做收尾处理。

## 2. 我们的现状与差距

| 项 | 参考图 | 我们现在 | 差距性质 |
|---|---|---|---|
| 河水 | #495264 (73,82,100) | **#327bc7** (50,123,199) | 亮度/饱和度偏高一档，色相差 60° |
| 河岸 | #565860，13%/侧 | **没有** | 缺失 |
| 近岸海水 | #495264（= 河水） | **#7a8495** (122,132,149) | 抬升 +69 vs +25，且往**灰白**走 |
| 深海 | #303949 | #353f53 | 略亮、略偏紫，可接受但要一起对齐 |
| 水面噪声 | σ 1–3/255 | 3 octave fBm × contrast 3.0 × shore_lift 0.85 | 幅度大一个量级，是"雾"不是"水" |
| 入海口 | 无缝（同色） | 亮蓝撞白雾 → 像撞墙 | 由上面两行导致 |

**"用力过猛"的定量解释**：我们的岸边带把水从 #353f53 抬到 #7a8495（+69/+69/+66），
参考图只从 #303949 抬到 #495264（+25/+25/+27）——**2.7 倍**；更关键的是方向：
我们抬向 `PALE_TINT #a8b3c2`（低饱和灰），参考图抬向的仍然是一个**饱和的蓝**。
灰→像雾，蓝→像浅水。这是观感差异的根，不是参数没调好。

## 3. 配色模型（单一真源）

四个常量，全部来自参考图实测，集中放在 `planet.gd`：

| 常量 | 值 | 来源 |
|---|---|---|
| `WATER_COLOR` | `(0.2863, 0.3216, 0.3922)` = **#495264** | 参考图河水 / 近岸海水逐一实测 |
| `WATER_DEEP_RATIO` | `(0.658, 0.695, 0.730)` | deep/shallow 逐通道比 |
| `WATER_BANK_MIX` | `0.20` | 反解 `mix(water, land, t) = 观测河岸` |
| `WATER_LAND_REF` | `(0.5451, 0.4392, 0.3137)` = #8b7050 | 只用于推导河岸色，不参与渲染 |

派生：

```
WATER_DEEP_COLOR = WATER_COLOR * WATER_DEEP_RATIO          → #303949
WATER_BANK_COLOR = mix(WATER_COLOR, WATER_LAND_REF, 0.20)  → #565860
```

> 颜色管线已确认：本项目 `unshaded` + 直接输出，**ALBEDO 就是最终像素值**。
> 证据：设定 (0.20,0.48,0.78) → 实测 #327bc7 (50,123,199)，与 #337ac7 差 1/255。
> 所以上表的值可以逐像素命中，**不需要任何 gamma 校准**。

## 4. 实现方案

### 4.1 海面：用长距离浅→深渐变替换白雾带

`planet_surface.gdshader` 的水格分支，整段替换：

```glsl
// 现在（概念）
band_water = t * (ocean_flat*macro) + (1-t) * k * (ocean_flat*macro);
float ramp  = smoothstep(0.04, 0.85, s_eff);
float gain  = ramp * shore_lift * (0.25 + 0.75 * c2);   // ← 最多混 85% 白
ALBEDO = mix(band_water, PALE_TINT, gain);

// 改后
float w = pow(clamp(v_tile_color.a, 0.0, 1.0), 0.9);    // 1 = 岸线，0 = 深海
vec3  water = mix(ocean_deep, ocean_flat, w);           // ocean_flat 语义改为「浅水色」
water *= 1.0 + (macro_luma - MACRO_MEAN_LUMA) * 0.30;   // ±2~3% 的弱斑驳
ALBEDO = water;
```

要点：

- `ocean_flat` 的语义从"Ocean 卡均色"改为"浅水色 = #495264"（值由 `planet.gd` 用
  `WATER_COLOR` 传入）。地表 shader 里不再需要 `PALE_TINT`、`shore_lift`、
  `shore_cloud_freq`、`cloud_edge`、`cloud_contrast`、`shore_macro`、`shore_strength`
  这一整套旋钮——**整块删掉**。
- 噪声复用**已经在采的** `macro_tex`，不新增采样。幅度用系数 0.30 把 ±10% 的宏观噪声
  压到 ±2~3%，落在参考图的 σ 区间。
- **fBm 整段删除**：`fbm3` 是 3 个 octave × 8 次 `hash13` ≈ 150 ALU/水面片元。删掉是
  净收益（见 §6）。如果后续觉得太"平"，再补一个**单 octave** `vnoise`（8 次 hash）
  的极低幅度版本，而不是恢复 3 octave。
- 覆盖区边界不变量保持：未探索水域同样按 `shore` 走同一条公式，没有特殊分支，所以
  边界不会出现亮度台阶（原来是靠"两格同用 ocean_flat"保证，现在是靠"同一公式"保证）。

**渐变长度**：靠 `SHORE_BAND_HOPS`（`ring_w` 上限）控制。参考图的渐变跨度 ≈ 屏幕宽度的
22%，对应我们近景视野（约 30° 宽）的 ≈ 6.6° ≈ **6 个贴片**。所以：

```
SHORE_BAND_HOPS: 4.0 → 6.0
```

### 4.2 河道：纯色 + 河岸带

`planet_rivers.gdshader`，只改 fragment，**几何与顶点一个都不动**：

```glsl
float e = abs(UV.x * 2.0 - 1.0);           // 0 = 河心，1 = 边缘
float aa = max(fwidth(e), 1e-5) * edge_softness_px;
float bank = smoothstep(BANK_INNER - aa, BANK_INNER + aa, e);  // BANK_INNER = 0.74
vec3  col  = mix(river_color.rgb, river_bank_color, bank);
ALBEDO = col;
ALPHA  = river_color.a * v_alpha * coast * (1.0 - smoothstep(1.0 - aa, 1.0, e));
```

- `BANK_INNER = 1 - 2 * 0.13 = 0.74`：即两岸各占水带外侧 13%（对应 UV 每侧 26%）。
- 河岸色、河水色都由 uniform 传入（`river_bank_color` 新增 1 个 vec3 uniform）。
- **河岸不额外消耗几何**：不加三角形、不加顶点、不加 draw call。
- 河宽口径：河岸算在河道总宽之内（和参考图一致）。代价是"水芯"从 100% 缩到 74%；
  若觉得细，把 `RIVER_HALF_MAX` 从 `0.00320` 微调到 `0.0035`（全宽 34% → 37% 贴片，
  仍在 `≤40%` 的玩法护栏内），**不要**为了补偿把总宽拉到 45%。
- 源头端头（`RIVER_TIP_TAPER` 0.30）与 alpha 渐隐照旧，河岸随宽度同比收窄，自动消失。
- 湖泊与河宽分级逻辑不变。

### 4.3 入海口：什么都不做

这是本方案最重要的一条：

> 河水 = 浅水 = #495264，入海口两侧本来就是同一个值，
> 加上 §24 的岸线裁剪已经在**最后一块陆地贴片的边线**上把河道切断，
> 所以拼上去就是严丝合缝的——参考图正是这么做的。

因此**上一轮规划里的两套机制全部取消**：

| 取消项 | 原方案 | 为什么不要了 |
|---|---|---|
| `COLOR.b` 存弧长距离 + `mouth_fade` | 河口最后 1.2 个半宽内 mix 到海色 | 两侧同色，mix 前后是同一个值，纯浪费 |
| 河口局部抑制白雾带（BFS 4 跳 taper） | 让河汇进深水而不是撞白墙 | 白雾带本身就不存在了 |

顺带也不需要"河口喇叭口"加强——`RIVER_MOUTH_FLARE` 保持 1.15 不动即可。

## 5. 为什么这次不是"打补丁"

对照用户的原则"自然优雅地从头绘制，不要画完再补"：

- 上一轮方案：河是 A 色、海是 B 色 → 在交界处**补**一段过渡；海边有白雾 → **补**一个缺口。
  两处补丁，且补丁本身的参数还要互相对齐。
- 本方案：把河与海**定义成同一个常量派生出来的颜色**，交界处没有"两侧"，补丁无从谈起。
  白雾带不是被削掉，而是**被换成了物理上正确的浅水色**。

参考图能这么干，是因为它只有一个水色常量；我们之前有两个（`RIVER_COLOR` 与
`ocean_flat`），各自独立演化，才会分叉。

## 6. 性能账（微信小游戏目标）

| 项 | 变化 | 说明 |
|---|---|---|
| **水面片元 ALU** | **−150 左右** | 删掉 `fbm3`（24 次 `hash13`） |
| 水面纹理采样 | ±0 | 噪声复用已有 `macro_tex` |
| 河面片元 ALU | +4 | 1 次 `smoothstep` + 1 次 `mix` |
| 顶点 / 顶点属性 | 不变 | 河岸是纯 fragment 效果，不占通道、不占带宽 |
| 面数 / surface / draw call | 1 / 1 / 1 不变 | 不加几何 |
| uniform 数量 | 河 +1（`river_bank_color`），地表 −7（白雾参数）/ +1（`ocean_deep`） | 不影响批次 |
| 每帧 CPU | 不变 | 无逐帧更新 |
| 构建期 | `SHORE_BAND_HOPS` 4→6，BFS 覆盖的水贴片变多 | 预计 +20~60ms（一次性，已纳入 slice 预算）；实施时实测上报 |
| 着色器变体 | 不变 | 只删分支、不加分支 |

净结论：**观感修复的同时，水面像素成本下降**（水面在大陆/海洋视角下占比很高）。

## 7. 风险与需要守住的不变量

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 去掉白雾后，远景（dist 10）海岸线辨识度下降 | 渐变仍有 +25/255 的抬升；陆地（橄榄）与水的色相差 60°，靠色相分辨；出图对比 dist 1.15 / 2.33 / 10.0 |
| R2 | 河岸 13% 在 1.6px 最小宽度下 <0.2px，等于没有 | 与参考图一致（细流本来就没有岸）；若观感需要，可用 `min_width_px` 微调 |
| R3 | 河岸色用固定 `#565860`，在雪原/沙漠上略"水土不服" | 参考图同样是固定色；先按固定做，看截图再决定是否按 biome 微调 |
| R4 | `SHORE_BAND_HOPS` 加宽后，覆盖区"强制浅滩外缘"可能出现亮度差 | 幅度只有 25/255（原来靠 0.85 白抬升会露白环，现在不会）；`test_planet_texture` 的小水域剔除与带宽自适应断言要复核 |
| R5 | 玄：`shore_verts / water_verts < 0.5` 这条旧断言会失败 | 带宽 4→6 后带内顶点必然变多，阈值要改成 `<0.75` 并按实际值校准（见 §8） |
| R6 | 河宽口径变化导致玩法护栏告警 | 河岸含在总宽内，`全宽 ≤ 40% L` 不变；只在水芯变细时微调 `RIVER_HALF_MAX` |

**必须保持不变**：
- §24 岸线裁剪（`COLOR.g` / `v_coast`）——一行都不动；
- 河网拓扑、河宽分级、Chaikin 平滑、圆角接头——不动；
- 图层顺序、`depth_bias` 视线偏移、`focal_px` 由 CPU 传——不动；
- 覆盖区边界"无亮度台阶"——改成"同一公式"保证。

### 11.2 代码落点

`planet.gd`：

```gdscript
const WATER_COLOR := Color(0.2863, 0.3216, 0.3922, 1.0)   # #495264 河水 = 近岸海水
const WATER_DEEP_RATIO := Vector3(0.658, 0.695, 0.730)     # → #303949
const WATER_BANK_MIX := 0.20                               # → #565860
const WATER_LAND_REF := Color(0.5451, 0.4392, 0.3137, 1.0) # #8b7050（只用于推导）
const RIVER_BANK_INNER := 0.74
static func water_deep_color() -> Color          # WATER_COLOR × WATER_DEEP_RATIO
static func water_bank_color() -> Color          # WATER_COLOR.lerp(WATER_LAND_REF, 0.20)
```

- `RIVER_COLOR` **删除**——河流材质改传 `WATER_COLOR`，与海面同源（这是本轮的核心：
  只有存在两个独立的水色常量时，才会分叉出"两种材质"）。
- 地表材质：`ocean_flat` = `WATER_COLOR`，新增 `ocean_deep` = `water_deep_color()`。
- `SHORE_BAND_HOPS` 4.0 → **6.0**。

`planet_surface.gdshader`（净减约 110 行）：

- 删除 `fbm3` / `vnoise` / `hash13`（≈150 ALU/水面片元）与 7 个白雾旋钮
  （`shore_lift` / `shore_cloud_freq` / `cloud_edge` / `cloud_contrast` /
  `shore_macro` / `shore_strength` / `PALE_TINT`）。
- 水格分支整段换成：

```glsl
float w = pow(clamp(v_tile_color.a, 0.0, 1.0), WATER_RAMP_EXP);  // 1=岸线, 0=深海
vec3 water = mix(ocean_deep, ocean_flat, w);
water *= vec3(1.0) + (macro - MACRO_MEAN) * ocean_macro;         // ±2% 弱斑驳
ALBEDO = water;
```

- `ocean_macro` 语义从"深海是否带宏观噪声"（默认 0）改为"水面斑驳强度"（默认 **0.20**），
  仍是现场可调旋钮，但不再"岸边单独加料"。
  **2026-10-24 回退**：用户反馈背面未生成深洋的 ±2% 宏观斑驳观感"脏"，默认值改回
  **0.0**（净色档，git 465998f 同款结论）；shader 默认 0.20 的记录以此条为准。
- 判断条件从 `v_is_water > 0.5 && v_tile_color.a > 0.001` 简化为 `v_is_water > 0.5`——
  深海（a=0）必须也走同一条公式，否则 `mix` 不执行、`ocean_deep` 永远用不上。

`planet_rivers.gdshader`：

```glsl
float full_px = 2.0 / max(fwidth(e), 1e-5);                    // 全宽的屏幕像素数
float inner = bank_inner * smoothstep(2.0, 5.0, full_px);      // 窄河收缩水芯
float bank = smoothstep(inner - aa, inner + aa, edge);
ALBEDO = mix(river_color.rgb, river_bank_color.rgb, bank);
```

- 只改 fragment：几何、顶点、属性、index、draw call 一个都没动。
- 圆角接头与河口圆盘的 `UV.x` 本来就是「圆心 0.5 / 环 1.0」，所以 `e` 天然等于半径比例 →
  河岸在这两种扇形上自动成为一圈边缘，不需要特殊处理。

### 11.4 踩坑

1. **`v_is_water > 0.5 && a > 0.001` 这个短路会让深海永远用不上新色**：深海 `a=0`，
   条件不成立就走 `tinted * macro`（色卡路径，水格色卡是 Ocean 均值）。必须去掉 `a` 判断。
2. `ocean_flat` 的取值来源换了，但 `biome_atlas.gd` 仍在算 Ocean 卡均色——保留无害
   （图集描述的一部分），但**不要**再拿它当海面色用，两者已经不是同一个东西。
3. GDScript 里写测试断言时注释是 `#` 不是 `//`（改着改着容易串）。
4. `get_shader_parameter()` 返回 `Variant`，`var x := ... if ... else ...` 推不出类型，
   必须显式写 `var x: Color = ...`。

### 11.5 仍未做 / 新观察

- **河口楔形尖角**：`RIVER_MOUTH_FLARE = 1.15` 让河口比岸线略宽，裁剪后跨过岸线的那部分
  变成一块楔形凸进海里（`temp/shots/trunk_gap.png` 放大可见）。颜色统一后它不再刺眼，
  但仍是几何缺陷；下一轮可考虑 `RIVER_MOUTH_FLARE = 1.0`（河口与河道等宽，裁出来就是平齐切口）。

  **`docs/planet_rivers_plan.md` §25**；推荐把河岸改成真正的几何内缩（同一份 mesh 画两遍）。
