## 0. 结论速览（含贴图问题的直接回答）

- **贴图需求 = 零，本次无需向项目导入任何新贴图。**
  原版世界太阳**没有任何贴图**——`World/Sun` 是 Material 不是 Texture2D，
  `Sun.json` 的 `m_TexEnvs` 为空，`Custom/Sun` 没有 `_MainTex`；白色核心、
  黄色内晕、柔和边缘全部由片元着色器用 UV 算出来。
  三处独立证据：
  - `23-Sun.md` §0 第 1 条与 §4.6（"答案：一张也没有"；唯一带 Sun 的
    `LampSun.png` 是本地地图灯具贴图，**与世界太阳无关**）；
  - `WorldMapTexturePaths.md` L459-460：复刻太阳"就抄 §4.4 的公式或替换
    shader，**不要去找 `Sun.png`**"；
  - 参考仓库工作树本身只有 `docs/` 与 `sources/`，无任何资产目录
    （`rimworld_assets/**` 不存在，就算想找也没有）。
- 星空所需的唯一贴图 `assets/stars.png`（原版 Stars.png）**已在项目里**，
  与太阳无关。所以"找到并导入贴图"这一步的工程答案是：**无事可做**——
  这不是偷懒，恰是原版设计本身（太阳是"相机相对 + 加法混合 + 程序化渐变"
  三件事，见 §9），也与本项目"全代码动态构建"惯例天然一致
  （`atmosphere.gdshader` 同样零贴图）。
- 若将来想要"贴图 sprite 风"的太阳（镜头光斑/光芒 sprite），那是另一条
  美术路线，**偏离参考对象**，届时再议，见 §3 方案 D。
- **落地形态**：一个跟随相机的 quad + 一个无贴图加法 shader + 一个由种子
  派生的 `sun_dir` 单一数据源；单 draw call，深度测试保留（星球自然遮挡太阳，
  等效原版双相机合成），零光照依赖。
- **明确不做**：物理太阳球体、`DirectionalLight3D`、Unity 双相机、
  太阳贴图 sprite、时间/季节摆动（昼夜联动留到期 3，公式存档 §5）。

## 2. 原版机制要点（对实现有约束力的结论）

只列对本项目实现有约束力的，全部引自 23-Sun.md：

1. **太阳是一个 quad，不是球**：局部 `forward*10` 处放边长 15 的 quad，
   4 顶点 / 2 三角 / 1 draw call。
2. **相机相对**：顶点着色器在 object-to-world 之后加 `_WorldSpaceCameraPos`
   → 中心恒为"相机前方 10 单位、沿太阳方向"，无视差；15/10 是为了固定
   **屏幕角尺寸**而选的参数，不是天体尺度（§3.3）。
3. **程序化径向渐变（零贴图）**，片元公式（§4.4）：
   ```
   d   = length(UV - 0.5)
   a   = max(0, 1 - 2*d)          # 中心 1，UV 半径 0.5 处归 0
   core = a^4                     # 白核集中
   rgb = min(1, core*(1, 0.847, 0) + a) * a
   ALPHA = 1
   ```
   核心暖黄 `(1, 0.847, 0)`，外加 `a` 抬中段亮度、`min` 饱和到白、
   最后再乘 `a` 平滑归零。
4. **加法混合 + 不测不写深度**：`Blend SrcAlpha One`（因 alpha=1 实为
   `dst + src.rgb`）；队列 `Background+1`(1001) 在星空(1000) **之后**。
   §4.7 明确警告：改普通 alpha blend 会出暗框/方形边界——黑色边缘靠
   "加法零贡献"淡出，不是靠 alpha。
5. **双相机合成**：天空相机(FOV 60)画星与太阳，世界相机(FOV 20)只清深度
   画星球 → 星球把太阳被挡的部分盖掉。§7.4 明确说 **Godot 不要硬搬双相机**。
6. **sunDir 是单一数据源**（§6）：`GenCelestial.CurSunPositionInWorldSpace()`
   从时间/季节公式算出单位向量，同时驱动四件事——太阳 quad 朝向、星空整体
   旋转、星球材质 `_PlanetSunLightDirection = -sunPos`（解析昼夜 `dot(N,sunDir)`）、
   大气辉光日照侧亮度（`0.28·sun² + 0.02`）。方向公式（§5.2/§7.5）：
   基础 `-Z`，每天绕 Y 转 `(dayPercent-0.5)×360°`，另有季节性 Y 偏移
   `±11.31°`（`curve(0)=0.2` 钳位的遗留）。
7. **星星避让太阳**：`dot(starDir, sunDir) > 0.8` 的星星缩小到 0.35×
   （`WorldLayer_Stars.cs:63-68`）。
8. **无 Unity 方向光**：太阳本体 unlit，星球明暗全是材质里的解析项。
9. **§3.3/§4.5 的角度表有自相矛盾**（行 1 用半边 7.5 是对的，行 2-4 的
   UV→世界半径换算把全边 15 当成 7.5，**少乘 2**）：落地时以 §4.4 的公式
   + 本项目自算几何为准，**角度数值不抄它的表**。

## 4. 系统设计（方案 B 展开）

### 4.1 文件与职责

| 文件 | 职责 |
| --- | --- |
| `sun.gdshader`（新） | `render_mode unshaded, blend_add, depth_draw_never, cull_disabled;`；fragment 抄 §4.4 公式（`d/core/rgb` 三行），**ALPHA 恒 1，靠 RGB 自身衰减淡出**（§4.7 的暗框坑）；`core_color`（默认 `(1, 0.847, 0)`）、`intensity` 做成 uniform——原版硬编码，文档 §7.3 建议复刻时留成属性，调参零改码。**颜色空间**：公式常量是线性值（§4.5「RGB 为线性值近似，未做 sRGB 转换」），Godot 的 ALBEDO 同样是线性值、由引擎输出时做 sRGB 编码 —— 两边一致，**不做任何手工 gamma 转换**（与本项目 `atmosphere.gdshader` 的同款约定）。注意 Godot 4.7 着色语言**没有** `srgb_to_linear()` 内置函数，别写 |
| `sun_quad.gd`（新，`class_name SunQuad extends MeshInstance3D`） | ① `_ready` 装配 `QuadMesh(SUN_QUAD_SIZE)` + ShaderMaterial；② 持 `direction: Vector3`（太阳方向，**一次赋值、多次消费**的接口）；③ `_process`：`global_position = cam.global_position + direction * SUN_DIST`（相机相对，等效原版顶点加相机位置）；basis 用切平面基一次对齐（quad 面 ⟂ 方向，含 UP 退化保护，不用 `look_at`）——径向渐变旋转不变，每帧只写 position，零重建；④ `static func derive_direction(seed, view_fwd)`：种子 → **首屏视线背后**（方位 180°±22°）的取景方向 |
| `planet.gd`（改，~25 行） | ① `_ready` 创建太阳节点（菜单相位即有，与星空同哲学）；② `_sun_dir` 数据源：默认方向给菜单相位，`_on_generate_requested` 里由 `seed` 派生新方向并传给节点；③ 大气辉光材质加 `render_priority = 20` 以钉死透明层叠次序；④ 期 3 起把同一向量喂给大气/地表 shader |
| `star_dome.gd`（改） | ① `build(seed, sun_dir)` 增加太阳方向入参；② 逐星 `rel *= sun_quad.star_shrink_factor(dir·sun_dir)` —— 落在太阳光晕可见圆盘内的星按原版规则缩小（**只改尺寸**，不改位置/亮度/数量 → 星空布局与确定性不变） |
| `orbit_camera.gd`（改） | 新增 `forward_after_focus(dir)`：预测 `focus_on(dir)` 之后镜头的真实朝向（**不移动镜头**），与 `focus_on` 共用同一套 yaw/pitch 夹取（`_sph_dir` 抽出共用）。生成流程靠它在 focus_on 之前就知道「首屏视线」——太阳取景与缩星都锚在它上面 |
| `tests/test_sun.gd`（新，GUT） | 结构断言 + 确定性 + 取景判据（**首屏隐藏** + **转镜头可发现**，后者按真实绕轨相机公式扫描 (yaw, pitch)）+ 缩星规则 + 拾取零耦合回归（见 §8），13 项全绿 |

### 4.2 参数表（已实现值，全部可调）

| 常量 | 实现值 | 依据 |
| --- | --- | --- |
| `SUN_DIST` | 15 | **下限约束**：必须 > `MAX_DIST(10) + PLANET_RADIUS(1)` = 11，否则最远视距下太阳平面会插进星球里、深度测试判错；15 留足余量（最坏情况——太阳背着星球、镜头拉到 10——平面离球心仍有 5 个单位）。上限：≪ 星穹 400、≪ far 4000。原版 10 是其固定视距下的值，不可照搬 |
| `SUN_SIZE_RATIO`（quad 边长 / SUN_DIST） | 0.8 | 原版 1.5（15/10）是配 60° 天空相机的值，光晕铺满全屏；本项目星球在默认距离 2.05 下就占屏高 58.4°，照搬会盖住半个天空 → 收到 0.8（实测截图确认比例合适） |
| `SUN_QUAD_SIZE` | `SUN_DIST × 0.8 = 12` | 由上两行导出，**只此一处引用**（吸取原版 `SunDrawSize` 死常量陷阱 §7.2） |
| `core_color` | `(1, 0.847, 0)` | 原版核心暖黄（shader 硬编码值），留 uniform |
| 角尺寸（按上式自算，**非**参考文档 §3.3 表） | a=0.9 白核 ≈ 9.1°；a=0.5 半亮区 ≈ 33.0° 全角；a=0 光晕边缘 ≈ 43.6° | UV 半径 × `SUN_QUAD_SIZE` 换世界半径再 `atan(/SUN_DIST)`。FOV 75 下：白核 ≈ 12% 屏高、半亮区 ≈ 44% 屏高、数学边缘 ≈ 58% 屏高；因双重 `×a` 衰减，感知是"小亮核 + 大范围低亮度柔光" |
| `HIDE_AZIM` | 180° | 太阳相对首屏视线的基准方位角。**180° = 视线的正后方** → 太阳整个在视锥之外（实测夹角 140°~180°，而视锥半对角才 ≈54°），首屏一帧不露。它是「藏在镜头后面」这条用户诉求的落点：太阳是纯加法混合的强光源，开局怼在画面里会晃眼、抢走「星球才是主角」的注意力 |
| `AZIM_JITTER` | ±22° | 基准方位角的随机抖动（左右对称区间 → 天然覆盖「左后方 / 右后方」两种手感）。不同世界的太阳藏在不同侧后方，转镜头去找它的手感不一样。抖动范围必须让「夹角 − 光晕角半径(24.2°)」仍 > 视锥半对角，否则光晕会漏进画面 |
| `ELEV_JITTER` | ±18° | 仰角抖动 → 太阳不会恰好贴在「正后正上」这个死点 |
| `SUN_RENDER_PRIORITY` | 10 | 太阳的透明绘制优先级（见 §4.3 渲染顺序行） |
| `ATMOSPHERE_RENDER_PRIORITY` | 20 | 大气辉光优先级，压在太阳之上（对应原版队列 3001 > 1001） |
| `_sun_dir` 派生 | 由 seed 在**首屏视线背后**偏置采样（方位 180°±22°、仰角 ±18°），锚点是 `focus_on` 落定后的**真实镜头朝向** | 全向均匀会约 80% 概率太阳落在首屏画面内 → 开局晃眼；偏置到正后方则**保证**首屏干净。取真实镜头朝向而非 `-_region_center`：focus_on 的俯仰夹在 ±77°，极端经纬下两者有微小偏差 |

### 4.3 关键实现语义（对照原版逐条）

| 原版语义 | 本项目对应 | 为什么不用原版写法 |
| --- | --- | --- |
| 顶点着色器加 `_WorldSpaceCameraPos`（相机相对） | `_process` 里 `global_position = cam.pos + sun_dir × 15`，basis 固定 | 等价效果零 shader 依赖；星穹同款手法，每帧一次赋值 |
| `ZTest Off / ZWrite Off`（双相机合成的一部分） | **深度测试开、深度写入关** | 单相机 + `SUN_DIST` 在星球最远表面之外 → 星球按深度自然盖住太阳，与星穹对 `ZTest Off` 的同款差异处理 |
| 队列 1001 > 星空 1000（光晕叠在星点上） | **用 `Material.render_priority` 显式钉死**：星穹 0 → 太阳 10 → 大气辉光 20，与原版队列 1000 < 1001 < 3001 逐一对应 | 靠距离排序会得到**相反**结果：星穹节点原点贴着相机（距离 0），back-to-front 排序下它会排到最后、盖住太阳。优先级是唯一可靠的表达方式（`Material.render_priority`：数值越大越靠前绘制） |
| 双相机挡太阳 | 深度测试 | 文档 §7.4 明确勿搬双相机 |
| `Blend SrcAlpha One` + alpha=1 | `blend_add` + `ALPHA = 1` | Godot `blend_add` = `SRC_ALPHA, ONE`，alpha=1 时即 `dst + rgb`，与原版等价 |
| 太阳方向 = 时间/季节公式 | seed 派生的静态方向（期 1）；§7.5 公式存档（期 3） | 项目无时间系统；`sun_dir` 接口先立 |
| 原版：太阳是世界固定方向，世界相机绕星球转 | 同样处理：`sun_dir` 是**世界方向**，太阳方片贴在「相机 + 方向 × 15」处 → 转镜头时它像真的那样在天空里移动（视差由相机相对定位消除） | **这条决定了「转镜头才看得到」的全部几何**（下详） |
| 星星靠近太阳缩小 0.35× | ✅ 期 2：`star_dome.build(seed, sun_dir)` 传入太阳方向，逐星 `rel *= star_shrink_factor(dir·sun_dir)` | 缩的判据是「落在**光晕可见圆盘**内」，阈值由 `glow_disc_cos()` 从我们自己的光晕几何导出（**不照抄**原版常数 0.8 —— 那是原版自己的光晕边缘，我们的光晕更小）；只改尺寸不改亮度/位置，与原版一致 |
| 原版星空层随太阳旋转（`Rotation = LookRotation(sunPos)`） | 不旋转：星穹固定在世界坐标，太阳方向也是固定世界方向 | 无昼夜系统（期 3 才引入），星空不需要跟着转；且**点积与旋转无关** —— 原版在图层局部系算 `dot(starLocal, forward)`，我们算世界系 `dot(starWorld, sunDir)`，两者等价（旋转保内积） |
| 无方向光 | 不加灯 | 全 unshaded 不变 |

### 4.3.1 首屏取景：「太阳藏在镜头后面」的几何（实测）

用户诉求：**首屏画面里不要出现太阳**（它太亮、开局晃眼、喧宾夺主），
玩家转动镜头到对应方向后才能看到它。

太阳是**世界固定方向**，而本项目的相机**永远看向星球中心**（绕轨）。
这两条一叠加，就得到一张完整的「可见性地图」—— 全部为实测量：

| 相机绕到哪一侧 | 视线与太阳方向夹角 | 画面里看到什么 |
| --- | --- | --- |
| 太阳这一侧（= **首屏状态**） | ≈180° | 太阳在镜头**背后**，视锥外 —— **一帧不露** |
| 正对太阳 | ≈0° | 星球恰好挡在中间 → **全食**，只见一圈日冕（逆光边缘） |
| 侧后方 | ≈29°~54° | 太阳从星球边缘**升出来**，日面完整可见 ← 「找到它」那一刻 |
| 再远一点 | >54° | 滑出画面外 |

- 视锥半对角：FOV 75 / 16:9 → 水平半角 **53.76°**、竖直半角 37.5°；
- 星球角半径（默认距离 2.05）：`asin(1/2.05)` = **29.20°**（拉远到 10 → 降到 5.7°，
  可见窗口随之变宽）；
- 太阳方片角半径：`atan(6/15)` = **24.23°**（光晕可见圆盘边缘）；
- 首屏夹角实测 **140°~180°** —— 减去 24.23° 的光晕半径仍 > 53.76°，
  **连一丝光晕都漏不进画面**。

「可见窗口 = 夹角 ∈ (星球角半径, 视锥半角)」是这套几何的必然结论，
也正是原版世界视图的同构行为（远处的固定光源 + 绕轨的相机）。
拉远镜头（星球变小 → 角半径变小）会让窗口变宽、更好找。

> ⚠️ 派生推论（**已在代码里踩过**）：镜头**正对**太阳时看到的是全食，
> 不是日面。想看日面得**偏一点**，让太阳从星球边缘露出来。
> 调试时用 `focus_on(-sun_dir)` 只能得到全食画面，不是 bug。

### 4.4 与现有系统的耦合边界

- 拾取：纯数学只对单位球求交，太阳 quad 永远不会被点中（零改动、零回归）；
- 拖拽/缩放：太阳每帧贴相机位置，与星穹一致，无视差滚动；
- 二次生成：换 seed → 重铺星穹（`build()` 会重算缩星）+ 改 `direction`；
- 大气/星空/HUD/菜单：期 1 不感知太阳；期 2 起星穹**消费**太阳方向（只缩星点尺寸，
  不改星点位置/亮度/数量 → 星空布局与确定性完全不变）。

## 5. sun_dir 单一数据源与昼夜联动（接口先立，分期实现）

原版最值得照搬的不是太阳画法，而是**"先定太阳向量，再让所有东西从它派生"**
（§6）。本项目落地为：

```
planet.gd: var _sun_dir: Vector3          # 唯一数据源（seed 派生 / 菜单默认）
    ├── sun_quad.direction                # 期 1：太阳 quad 朝向
    ├── star_dome.build(seed, sun_dir)    # 期 2：星星避让（dot>0.8 缩 0.35×）
    ├── atmosphere: uniform sun_dir       # 期 3：日照侧提亮
    │     intensity = a³ × (0.28·sun² + 0.02)   # 原版公式，替换固定 0.42
    └── planet_surface: uniform sun_dir   # 期 3：解析昼夜 dot(N, -sunDir)
```

期 3 的时间公式（原版 §7.5，存档备用，**本期不实现**）：

```
day_percent = (abs_tick % 60000) / 60000
day_of_year = (abs_tick % 3600000) / 60000      # 0..59
season_y    = -cos(day_of_year / 60 * TAU) * 20 # curve(0)=0.2 钳位 → ±11.3°
v = Vector3(0, season_y, -100)
v = rotate_y(v, (day_percent - 0.5) * 360°)
sun_dir = normalize(v)
```

> 注意期 3 是**观感大改**（星球将出现明暗半球），必须单独拍板后再动，
> 不与太阳本体捆绑。

## 6. 分期与工作量

**期 1（已完成）：太阳本体**
1. ✅ `sun.gdshader`：公式三行 + 加法/深度模式 + 两个 uniform；
2. ✅ `sun_quad.gd`：装配 + 相机跟随 + 方向接口 + UP 退化保护 + 种子派生取景；
3. ✅ `planet.gd` 接线：`_sun_dir`（菜单默认 + seed 派生）+ 建节点 + 大气优先级；
4. ✅ GUT 结构测试 7 项 + 截图调参（四档 dist + 转向/遮挡构图各一张）。

**期 2（已完成）：星星避让（光晕内的星缩小）**
- ✅ 语义照搬原版 `WorldLayer_Stars.cs:63-68`：`dot(starDir, sunDir)` 超过阈值
  → 星点尺寸按 `1 + (0.35-1)·t` 线性缩小（正对太阳 0.35×，光晕边缘 1.0×）。
- ✅ **阈值不照抄原版的常数 0.8**。那个 0.8 不是魔数：它恰好等于原版太阳
  「光晕可见圆盘」的边缘（方片半宽 7.5 @ 距离 10 → atan(7.5/10)=36.87° → cos=0.8），
  语义是「**落在光晕里的星星缩小**」。我们的光晕更小（比例 0.8 → 半宽 6 @ 距离 15
  → 21.8° → cos≈0.928），照抄 0.8 会让光晕外一圈星星无故变小。
  阈值改由 `sun_quad.glow_disc_cos()` 从**我们自己的光晕几何**导出 ——
  改 `SUN_SIZE_RATIO` / `SUN_DIST` 时阈值自动跟着走，缩星范围永远等于光晕范围。
- ✅ 实现落点：`star_dome.build(seed, sun_dir)` 增加太阳方向入参，逐星算
  `rel *= sun_quad.star_shrink_factor(dir·sun_dir)`（**只改尺寸**，不改亮度/位置，
  与原版一致 —— 原版缩的是 quad 的绘制尺寸）。
- ✅ 方向一致性：太阳方向在生成流程**开头**定一次（`_sun_dir`），星空缩星与
  太阳本体共用同一个值 —— 否则缩掉的不是这颗太阳旁边那批星。
  锚点用 `orbit.forward_after_focus(_region_center)`（与 `focus_on` 共用同一套
  俯仰夹取，逐位一致，且不受生成过程中玩家拖动镜头的影响）。
- ✅ GUT 4 项 + 实测（种子 4242）：光晕圆盘内 620 颗星中 610 颗被缩，
  远端 15380 颗一颗未动；截图对比可见光晕区星点明显变小、远空依旧细碎。

**期 3（可选，昼夜联动——观感大改，单独拍板）**
- 大气日照侧提亮（原版 `0.28·sun²+0.02` 公式）；
- 地表解析昼夜 `dot(N, -sunDir)`；
- 若引入时间系统：§5 存档公式 + 星空随太阳旋转。

**明确不做**（写进规划避免歧义）：物理太阳球、`DirectionalLight3D`、
双相机、太阳贴图 sprite、星星闪烁、太阳被云/大气折射之类的拟真效果。

## 9. 一句话总结

**一个由种子派生方向的相机相对 quad（每帧 = 相机位置 + sun_dir × 15）+
一个零贴图的加法 shader（原版 §4.4 径向渐变三行公式，核心暖黄、ALPHA 恒 1
靠 RGB 衰减淡出）+ 一个 `sun_dir` 单一数据源（期 3 昼夜联动的锚点）——
单 draw call、深度测试自然遮挡、零光照依赖、零新贴图。**

> 与原版的三处有意差异：① 单相机深度测试替代双相机合成（文档 §7.4 认可的
> Godot 路线）；② 方向来自种子而非游戏时间（项目无时间系统，公式存档 §5）；
> ③ 菜单相位也显示太阳（本项目菜单背后即天空）。原版的精髓
> "**相机相对 + 加法混合 + 单一 sun_dir**"三件事一件不丢。
